# 实测记录：真实模糊原话（纯剪发范围）

测试方法：每条原话走完整四段流水线，检查是否命中歧义模式、是否触发正确追问、输出是否可执行、**每一项是否可溯源到用户原话**。

**通过标准**：
1. 每条都能产出带数字的指令卡，无模糊词残留
2. 不越界处理烫染
3. **卡片每一行都能回指到用户说过的话**（第三轮新增的硬判据）

---

## 一、高频模糊表述

### 1. 「剪短一点但别太短」
- 命中：模式 A（无量词陷阱）
- 追问：「A 剪到耳上（6cm）／B 耳垂（10cm）／C 后颈（3cm）？」
- 产出：长度量化 ✓
- 溯源：长度维度，用户原话「短一点」+ 追问选定✓

### 2. 「修一下就行」
- 命中：模式 A（修一下的两种含义）
- 追问：「只剪分叉长度不变／还是整体剪短？」
- 产出：区分修分叉 vs 剪短 ✓

### 3. 「两边弄短点」
- 命中：渐变起点未定义
- 追问：「低渐变（耳上）／中渐变（耳中）／高渐变（耳上至太阳穴）？」
- 产出：过渡带位置量化 ✓

### 4. 「想显精神」
- 命中：模式 C（形容词双向失效）
- 追问（第三轮修订）：「精神你想靠哪儿？Ａ 靠两侧（推剪+露额）Ｂ 靠头顶（留长+层次撑起来）Ｃ 靠整体（统一剪短）」
- 产出：用户选定后只写对应维度，**不给「短碎发」这类发型名** ✓
- 溯源：每个维度均有用户选择背书 ✓

### 5. 「留个刘海」
- 追问：「空气／齐／八字／碎刘海？」
- 产出：类型 + 位置（眉上 1cm）✓

### 10. 「修一下发尾」
- 产出：打薄 + 内扣/外翻 + 长度数字 ✓

## 二、修饰意图类（第三轮修订：改为追问，不自动落方案）

### 9. 「想显脸小」
- **原产出（越界）**：两侧收窄（低渐变）+ 露额 + 发尾不厚重
- 现产出：追问「靠哪个部位：两侧收窄 / 露额 / 发尾贴脸？」，用户选中后才出该行 ✓
- 溯源：三行都有用户选择背书 ✓

### 6. 「头发太塌了」
- **原产出（越界）**：层次方案（高层次增加发根支撑）／两侧方案（推剪收窄）／长度方案
- 现产出：追问「靠头顶撑起来（层次），还是靠两侧剪短变利落？」，不预设层次类型 ✓
- 判定：蓬松是效果描述，不是剪法指令，**「高层次」不作默认**

### 7. 「显得温柔一点」
- **原产出（越界）**：中长发 + 空气刘海 + 内扣 + 层次感
- 现产出：追问「想靠刘海柔和感，还是靠发尾内扣？」，不预设中长发 ✓

### 8. 「别太老气」
- **原产出（越界）**：暴露额头的处理、避免齐刘海、侧分或碎盖
- 现产出：追问「你想改额头那块，还是改刘海那块？」，让他选改动位置 ✓

## 三、溯源越界专项（第三轮新增对照表）

| 输入 | 越界版本（修前） | 合规版本（修后） |
|---|---|---|
| 我想显脸小 | 直接给「露额 + 两侧收窄」 | 追问靠哪个部位，让用户挑 |
| 头发太塌想蓬松 | 直接给「高层次 + 高渐变」 | 追问靠头顶还是靠两侧 |
| 头发太塌想蓬松（卡片维度） | 额外塞入刘海/发尾内扣 | 用户未提及 → 该行不输出 |
| 我适合什么发型 | 给出推荐发型 | 声明不做推荐，转为追问用户想改变什么 |
| 细软 + 低层次 | 「建议改中高层次」 | 提示物理不可行 + 问要不要换，不替他换 |

**这张表是本 Skill 的核心回归基线。** 每次改动后对照检查，防止越界行为回流。

### 13. 「稍微修一下，千万别剪太短」

- 产出：底线「最多剪 2cm」显式写入卡片 ✓

## 十、第四轮：把 L2 的假绿灯修成真判据（2026-10-19）

用户实测反馈「基础术语翻译可用了」。复核测试体系时发现：**L1 是准的，L2 是假的**。

### 问题定位

`check_lexicon_coverage.py` v1 第 87 行：

```python
hit = [kw for kw in expect_keywords if kw in glossary]
```

拿关键词去 166 行词典全文做子串包含。只要这几个字在任意一行出现过一次，用例永远通过。测的是「这个词你写过没有」，不是「这条原话能不能正确映射」。

**误命中实证（4 例）**：

| 原话 | v1 判定 | 正确处置 | 性质 |
|---|---|---|---|
| 想显脸小 | 命中`渐变` | 效果描述 → 追问部位 | 因为「渐变」在别处出现过 |
| 别太老气 | 命中`刘海` | 效果描述 → 追问部位 | 同上 |
| 显得温柔 | 命中`空气刘海/内扣` | 效果描述 → 追问部位 | 两条都是模型推的 |
| 剪短点薄点能扎上就行 | 命中`层次` | 打薄（用户说了「薄点」） | 万能词蒙混 |

更严重的是**测试集本身在教模型越界**：「想显脸小」的期望被写成「命中渐变」、「头发太塌了」被写成「命中高层次」。用这样的测试集训练出来的绿灯，正好盖章了第三轮刚删掉的那种偏移。

### v2 判据设计

1. 只解析含「口语别名」列的表格，**只在别名列比对**。效果/特征/适配脸型列不参与——这把 glossary 的「使用纪律」变成了机检。
2. 命中必须落到某一行，且该行标准术语等于期望值（行级判定，不再全文匹配）。
3. 引入**负样本**：效果描述 / 只说维度没说类型 / 只是发质信息 → 必须零命中，命中即判越界。
4. 引入**判据自检**：先跑 3 组「故意给错期望」的反向用例，全部判红才继续。判据恒真时直接退出。

### 修改前后对照（同一份词典）

| 指标 | v1 | v2 |
|---|---|---|
| 用例数 | 31（全正样本） | 33（16 正 + 17 负） |
| 判据 | 全文子串包含 | 行级别名反查 + 术语一致 |
| 能否抓越界 | ❌ 不能 | ✅ 17 条负样本专抓 |
| 首轮结果 | 31/31「全绿」 | **26/33，7 条报红** |

**7 条报红的归因**（这就是 v1 藏起来的东西）：

| 报红用例 | 归因 | 处理 |
|---|---|---|
| 两边推短 | 词典缺口：渐变行没有这个说法 | 补别名 |
| 两边剃光 | 词典缺口：铲青行只有「两边推光」 | 补别名 |
| 鬓角弄利落点 | 词典缺口：推边行只有「鬓角推剪」 | 补别名 |
| 层次感强一点 | 词典缺口：高层次行无「层次感强」 | 补别名 |
| 剪短点薄点能扎上就行 | 词典缺口：打薄行无「薄点」 | 补别名 |
| 后脑勺修的圆满一点 | **结构性缺口**：全库无颈线术语 | 新增第五节「后颈收边」 |
| 后面留个台阶 | 同上 | 同上 |

补词只补「用户真的会说、词典真的没有」的说法，不改任何判定期望——这是 L2 的正当用途，不是应试。

### P0-2：两处结构性缺口

**缺口一 · 后颈收边无术语**。词典原本只有「后颈发际线」一个长度锚点，`grep 圆弧|颈线|neckline` 零命中。而「圆满 vs 台阶」是真实分歧点（用户真实原话「后脑勺修的圆满一点」）。新增第五节：

| 术语 | 别名 | 判据 |
|---|---|---|
| 圆颈线 Rounded neckline | 圆弧收边、后脑勺修的圆满、圆着收 | 沿发际线连续弧线，中间不留平直段 |
| 方颈线 Square neckline | 台阶、留个台阶、后面留一道 | 两角垂直，中间水平线 |
| 自然颈线 Natural | 顺着长、后面别动 | 只清杂发，不改走向 |

并强制量化两项：弧度起点（耳后/耳垂延长线）+ 收边高度（发际线上方 0-2cm）。只说「修圆」不说高度，师傅会一路推上去。

**缺口二 · 整体约束型原话无归宿**。「修一下就行」「就稍微剪剪」「保持原样」不落在六维任何一维，旧卡片模板也没有对应区块，结果会被硬塞进长度维——翻译成「剪 3cm」，而用户本意是「别改结构」。这两件事剪出来完全不同。

处理：新增【整体约束】区块，明确**它不是第七维**。区分标准写进 SKILL.md 第 2 段第 8 条：能落到某个部位的是维度，描述「改多少/改不改结构」的是约束。卡片里补了正反对照——「稍微修一下」写成「顶部剪短 3cm」是典型误译。

### 验证结果

| 层 | 结果 |
|---|---|
| L1 静态 | **85/85 通过**（71 → 85，新增第八组：后颈术语 6 项 + 约束区块 4 项） |
| L2 词典覆盖 | **33/33 通过**（16 正 + 17 负），含判据自检 3/3 |
| L3 行为 | **17 条**（15 → 17，新增用例 16 整体约束 / 17 后颈收边），待人工实跑 |

### 本轮踩的坑

- **术语名带分隔符**：词典里「铲青 / 底切」「方颈线 / 台阶」是一行多名字，直接 `expected in row_term` 会漏判。改为按 `[／/、空格]` 拆开逐个比。
- **别名粒度要跟口语粒度对齐**：收了「薄一点」仍漏「薄点」。用户嘴里的说法不会按你的分词粒度长。

## 十一、P1 第一轮：追问预算 / 两步推理 / 长发场景（2026-10-19）

P0-3（真实剪发验收）搁置，先做 P1 里不依赖外部数据的三块。

### P1-1 · 追问预算：给追问本身设上限

溯源闸门逼着模型追问，但**追问会退化**——连问三轮、每轮三问，用户会关掉页面。过度追问和替用户选方案是同一种失败的两端：一个伤体验，一个伤决定权。

SKILL.md 新增「追问预算」章节：

| 轮次 | 上限 | 问什么 |
|---|---|---|
| 第 1 轮 | ≤3 个问题 | 长度（不可逆）→ 两侧是否推剪 → 发质/发量 → 效果类问部位 |
| 第 2 轮 | ≤1 个问题 | 只问仍然阻塞出卡的那一项 |
| 第 3 轮 | **禁止** | — |
| 超预算 | 出卡 | 未定项标 `[待确认]` + 写清后果 |

**三个例外**：用户主动要求系统描述（转模板）、用户明确交权（「你看着办」）、安全类信息缺失。

**核心判断：授权默认 ≠ 静默默认。** 用户说「你看着办」时，模型**可以**给值——这是用户主动交权，溯源成立；但必须在卡片旁标出来源并留否决权（「长度是我按你说的『别太短』推的 B 方案，不对就否掉」）。区别就在这一句标注上：没有它，和「第三次追问失败后自己填一个」是同一件事。

### P1-2 · 模式 H：语义等价 ≠ 可以代填

这是 testing-guide 里挂了最久的那条盲区（「用户说蓬松→模型给高层次，算不算越界」）。这轮把它从「等盲测积累」变成判定条款。

模式 G 抓的是「效果直接给方案」，错误看得见。模式 H 抓隐身版本：模型不直接给方案，而是走两步——「用户说蓬松 → 蓬松对应高层次 → 卡片写高层次」。中间那步在模型脑子里完成，用户看不见，但结果一样是代填。

**五档判定**（写进 failure-cases）：

| 用户原话 | 卡片写 | 判定 |
|---|---|---|
| 说了术语或口语别名 | 该术语 | ✅ 引用 |
| 说了维度 + 方向 | 该方向标准术语 | ✅ 引用 |
| 说了维度没给类型 | 该维度具体类型 | ❌ 越界 |
| 只给效果 | 具体术语 | ❌ 越界 |
| 只给效果，但追问中用户选了 | 用户选的那项 | ✅ 引用（显式确认） |

**判据一句话**：这一行能不能回答「用户在哪句话里选过它」——答案必须是**引用**，不能是**推断**。

**自检入口**：当你想说「用户显然会想要」时，那个「显然」就是两步推理的入口。

### P1-3 · 长发场景：补锚点而不是补文案

判例里那一剪刀 60cm 就是长发场景。原词典的锚点表只到「锁骨」，长发用户说「剪到胸口」无处落地。

- 补三个长发锚点：**肩线**（肩峰水平线）、**胸线**、**腰线**
- 补别名：锁骨发 ← 剪到肩/齐肩；齐发尾 ← 一刀切；零层次 ← 别打层次/不要层次
- L2 新增 6 条：正样本「剪到肩膀」「发尾一刀切」「别打层次」；负样本「到腰的长发」（只是陈述）「想显瘦一点」（效果）「别剪太碎」（否定句式）

「别剪太碎」这条专门守**否定句式不得被正向匹配**：用户说的是不要碎剪，若词典把它匹到碎剪，翻译就反了。

## 第五轮：追问用语（问句必须落在顾客参照系）

### 问题来源

用户实测反馈：模型读完需求后，**进一步确认的问题里带着专业术语，而且 3mm／5mm 这类数字普通人没有概念**。追问环节本身失效——用户答不上来，选项形同虚设。

### 根因（不是措辞问题，是规则缺位）

| 位置 | 缺什么 | 后果 |
|---|---|---|
| SKILL.md 第 2 段 | 只要求「追问必须带数字」，无任何用语约束 | 模型学会带数字，学会的是卡尺编号 |
| SKILL.md 第 3 段 | 「目标效果：用户听得懂」只约束**指令卡**，不约束**追问** | 出卡时说人话，追问时说黑话 |
| 对外表达规范·状态 A | 示例是好例子，但规则清单里没有禁令 | 模型只学到那一个例子的形状 |
| failure-cases 模式 A | 表格里写着「推剪到 3mm？还是留 2cm 碎发？」 | 引用文件是模型最易照抄的句子来源 |
| glossary 单位表 | **`1cm` 被写成「约 3mm」**（实为「约 3 分」，1 分 ≈ 3.2mm） | 差 3 倍，长度翻译全线走样 |

### 核心判断：数字错在参照系，不在精度

理发师的参照系是「剪除量 + 卡尺编号」，顾客的参照系是「看得见的结果」。**两套体系不通，数字加得再多也换不来理解。**

尤其 mm：它是**推完留在头上的长度**，不是剪掉的量。顾客听到「留 5mm」，多半理解成「只剪掉 5mm」——他以为很保守，实际是贴头皮推一遍。这是所有失败里最危险的一种：**顾客以为自己同意了很保守的方案。**

### 改动清单

- `SKILL.md` 第 2 段新增「追问用语规则」五条（位置问长度／mm 禁入问句／术语换人话／选项须可验证／一个问句最多一个专业词）
- `SKILL.md` 对外表达规范·状态 A 规则清单新增禁令（输出阶段才是真正生成问句的地方，只写在第 2 段不够）
- `SKILL.md` 失败模式表新增 2 行（追问用术语或卡尺数字、追问选项顾客验证不了）
- `glossary-cutting.md` 修正 `1cm = 3mm` → 「约 3 分」，并加卡尺语义警示
- `glossary-cutting.md` 新增「双参照系」对照表（8 组：❌ 理发师语言 / ✅ 顾客语言）+ 两条硬规则
- `failure-cases.md` 模式 A 表格去掉「推剪到 3mm」，改为可验证结果；Skill 应对补数字归属说明
- `check_static.py` 新增第十组 `check_followup_language()`（14 项）
- `run_behavior_test.py` 新增用例 22（卡尺数字）、23（裸术语）
- `testing-guide.md` 新增「追问用语专项」章节 + 计数同步

### 验证

| 层 | 结果 |
|---|---|
| L1 静态 | **118/118**（104 → 118，新增第十组 14 项） |
| L2 词典 | **39/39** 不变 |

**变异测试**：把「约 3 分」改回「约 3mm」、把模式 A 改回「推剪到 3mm」，L1 精确报红 2 项，还原后 md5 校验一致、全绿。

**踩的坑**：第十组首跑有 1 项假失败——判据写成找「位置型数字」，正文写的是「不问剪除量」。**校验脚本自己也会错**，判据要照正文实际用词写，不能照自己脑子里的术语写。

### 仍未验证

追问用语规则是**模型行为约束**，L1 只能保证规则在、反例不回流，不能保证模型遵守。必须用用例 22/23 实跑，并做一次真实盲测（拿自己下次要剪的头发，看追问里还出不出现 mm）。

### 追加（同日）：追问的直观化——四个参照系

禁掉术语和 mm 只解决了「不说什么」，没解决「该说什么」。用户接着问：确认长短时怎么让顾客**直观**感受到。

**判据先行**：直观 = **用户不需要在脑子里做转换**。「剪 5cm」要转换（做不到）；「剪到耳垂」要想象（勉强）；「剪掉三指并拢那么宽」抬手就能比（直观）；「剪完还想不想能扎起来」不用想长度（最直观）。

**核心判断：长度是需要想象的概念，结果是此刻就能回答的事实。** 所以确认顺序改成**先定结果、再定位置**，而不是一上来问长度。

四个可换用的参照系：

| 参照系 | 适合 | 例 |
|---|---|---|
| 结果 | 全场景，优先 | 还能扎起来吗／耳朵露不露／盖不盖眉 |
| 位置 | 中长发 | 耳上／耳垂／后颈／锁骨 |
| 手部度量 | 1-20cm 短距离 | 三指并拢≈5cm／手掌宽≈8-9cm |
| 社会符号 | 短发 | 军训头／三天没刮的胡茬 |
| 现状对比 | 长发 | 比现在短一半／剪掉现在三分之一 |
| 捏发确认 | 用户说不清 | 捏住一撮，手指停的位置就是底线 |

**约束**：单次追问最多两种参照。三种全上，就是把选择题变成了问答题——直观化的目的是降低作答成本，不是展示参照物库存。

**改动**：SKILL.md 追问用语规则 1 扩为三参照 + 新增「结果优先」与「捏发兜底」（原 5 条变 7 条）；glossary 新增「顾客的随身参照尺」三表 + 「参照系怎么选」场景表；`check_static.py` 第十组 +9 项；L3 新增用例 24。

**验证**：L1 **127/127**、L2 39/39、L3 **24 条**。

**仍未被验证的**：模型会不会真的先问结果。这条只能靠用例 24 实跑——判定项第一项就是「首问是否为结果类问题」，出现「剪多长」直接判失败。

## 第六轮：照片输入（验证器，不是推荐器）

### 缘起

用户问：如果用户进一步提供四面照片，可以拓展什么功能。拍板做 P0（现状锚定、后脑补盲）+ P1（口径校准、到店坐标），暂不做 P2（差异说明）与脸型推荐。

### 核心判断：照片是唯一能推翻本 Skill 定位的输入

前五轮修的都是「说话方式」，这一轮引入的是**新的输入通道**。一旦允许「看图给建议」，第三轮拆掉的推荐引擎会立刻回来，而且这次带着照片当背书，用户更不容易察觉自己在被推荐。

所以先立边界，再谈功能：

| 照片可以 | 照片绝对不可以 |
|---|---|
| 读现状（发长落点、后脑形状、层次、两侧状态） | 判断脸型、五官、发质好坏 |
| 校验用户描述与事实的偏差 | 推荐发型、评价好不好看 |
| 给指令卡补精确坐标 | 凭照片直接决定剪法 |

一句话：**验证「他说的和实际是不是一回事」，不验证「他适合什么」。**

### 第二主线：成本控制

拍四张照片是用户的真实负担，所以设三条触发（改后脑／长发大改／追问两轮说不清），并明确「日常两边修短不要照片」。这跟「不默认甩模板」是同一条原则：**只有会改变结果的输入才值得收。** 并且只要必要的那一张，不要求四面全套。

### 价值不对称：一面顶三面

四面里只有**后面那张**不可替代。其余三面照镜子就能看见，后脑是真正的 180° 盲区，恰好又是颈线争议的发生地（圆颈线 vs 留台阶）。

### 口径校准不依赖照片

「剪到耳朵」可能是耳上缘／耳朵中段／耳垂。这层歧义用一句话就能拆，不需要照片——所以词典的「位置词口径表」是独立可用的，照片只是让它更快。

- `SKILL.md` 新增「照片输入」章节（验证器定位 / 三条触发 / 怎么开口 / 读图用位置 / 照片不能替代确认）

- `check_static.py` 新增第十一组 `check_photo_input()`（17 项）

## 后脑勺照片实测：能不能"标出高度"

### 测试设计

1. 生成后脑勺照：短发、后颈推短区与长发区之间有明显水平台阶线（典型的方颈线）
2. 独立执行者读 SKILL.md，用户诉求：「后面这个台阶太硬了，我想修得圆满一点，别留平的边」
3. 第一轮看它读到什么、问什么；第二轮用户选定「保持高度、只磨圆两个角」，看卡片给出什么坐标
4. 拿卡片描述**人工落点画到照片上**，验证可执行性

照片与标注结果：`工作区/test-assets/`（原图 + `_neckline_annotated.png`）

### 第一轮：现状读对了，但没标高度

输出：「后颈下面是一块推短的头发，边缘收成一条平直的线、左右两个角是方的」——与照片完全一致。随后追问两件事：高度动还是不动、圆弧从哪儿起弯。选项全是同维度改法，符合规则。

**这一轮没标任何东西，是对的**——用户还没确认高度，先标就是替用户决定。

### 第二轮：卡片给出的坐标长这样

```
【后颈】圆颈线 Rounded neckline
· 沿现在这条边缘线走一条连续圆弧，左右两个角磨圆，不留直角
· 弧度起点在耳后那条竖线，从这里开始往下转弯
· 边缘线的高度保持现状，不往上升，也不加高短发区
· 整条边缘不留平直段
```

### 结论一：给人执行，够用

这张卡里有三个可定位的东西：**现状边缘线**（照片里可见）、**耳后竖线**（解剖点）、**高度保持现状**（相对基准）。照这三句，人能画出目标弧线——`_neckline_annotated.png` 就是按它画的，形态正确。

而且"高度保持现状"这个说法比给一个 cm 数更准：它把不可逆的风险降到了零，因为根本不创造新高度。

### 结论二：给程序执行，不够

缺的不是精度，是**坐标系**。卡片用的是「解剖锚点 + 现状相对」，渲染要的是「图像坐标」。中间差一层识别：

| 卡片说法 | 落到像素需要 | 现状 |
|---|---|---|
| 沿现在这条边缘线 | 识别发际线在图像中的位置 | 未提供 |
| 耳后那条竖线 | 识别耳后与颈侧的交界 | 未提供 |
| 高度保持现状 | 先测出现状线的 y 值 | 未提供 |

**实测旁证**：人工落点时第一次画歪了约 300px（画到后脑长发区），第二次才对齐。人眼都需要试错，程序更不可能凭空猜。

### 结论三：正确的产品化路径是「让用户指锚点」，不是「让模型猜」

模型不该做像素级识别，猜错一个锚点整条线就偏了。可靠做法是请用户在照片上点两个位置（后颈边缘线最低点、左右耳后交界），模型只负责换算相对关系。

这条已写进 `haircut-card.md` 的「照片坐标」规则 4：**锚点由用户指认，模型只负责换算关系**。它和溯源闸门是同一个哲学——**推断不能替代用户的指认**，只是这次推断的对象从"审美偏好"变成了"图像坐标"。
