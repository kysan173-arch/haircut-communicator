# 用户输入模板

## 设计原则

模板的成败取决于**填表成本 vs 信息增益**的比值。填表太长，用户直接放弃；太短，第2 段追问还是要问一遍，等于白填。

所以核心策略是：**只有会改变剪法结果的字段才收，其余一律不收。**

---

## 何时使用

| 场景 | 是否给模板 |
|---|---|
| 用户需求模糊（占大多数） | **直接问关键问题**，不问模板 |
| 用户需求清楚但缺少发质信息 | 补问发质 + 发量 |
| 用户主动说「我要好好描述一下」 | 给完整模板 |
| 用户上传参考图（后续阶段） | 给精简模板，照片可替代部分字段 |
| 用户是长发修剪 | **必给模板**（长度底线是纠纷高发区） |

**默认不甩模板。** 大多数场景下问2-3 个问题就够了，甩一张表过来是体验倒退。

---

## 模板 A · 完整版（首次咨询 / 长发修剪）

```
【基础信息】（不确定的可写「不确定」，我会帮你判断）

1. 发质软硬：细软偏塌 / 正常 / 粗硬易炸 / 自然卷
2. 发量偏多还是偏少：偏少 / 正常 / 偏多
3. 日常打理：几乎不弄 / 简单吹两下 / 认真打理 / 每天都要弄
4. 当前长度：大约到（锁骨/肩膀/耳下/耳上/更短），也可以说「大概一年没剪」
5. 最不能接受的事：（可多选）
   □ 太短 □ 两边被推光 □ 显老 □ 显脸大 □ 头发炸开 □ 其他____

6. 这次想达到什么效果：____（用自己的话说就行，不用专业词）
```

---

## 模板 B · 精简版（用户已有明确目标，只补基础信息）

```
1. 发质：细软 / 正常 / 粗硬 / 自然卷
2. 发量：偏少 / 正常 / 偏多
3. 日常打理时间：几乎不弄 / 简单吹 / 认真打理
4. 最不能接受：太短 / 推光 / 其他____
```

四个问题，10 秒能答完，够用了。

---

## 字段设计说明

### 为什么只收这四类

| 字段 | 影响的剪法 | 不收会怎样|
|---|---|---|
| **发质软硬** | 层次可行性（细软禁忌低层次）、打薄必要性（粗硬不打薄会炸） | 可能给出物理上做不到的方案 |
| **发量多少** | 减量幅度（发量多需多打薄） | 发量多却只做低层次→ 剪完炸开 |
| **打理频率** | 层次与长度的兼容度 | 留长+高层次但用户不吹→ 塌 |
| **长度底线** | 硬底线规则的依据 | **纠纷的直接来源** |
### 为什么不收脸型

大部分用户自我诊断脸型不准（圆脸和鹅蛋脸的边界很多人分不清），问了反而得到错误输入，误导后续判断。

当前用**修饰方向**替代，但**只用来追问，不用来替用户选**：用户说「想显脸小」，追问「你想靠两侧收窄，还是靠露额，还是靠发尾贴脸？」，让他自己挑一个，挑完才写进卡片。不问就替用户定「露额+两侧收窄」，是设计不是翻译。

### 为什么不收具体想要什么发型

这是用户的核心诉求，必须让用户用自己的话先说出来。给了选项反而会引导用户往框架里凑，掩盖真实需求。**用户的模糊原话本身就是最有价值的信息**，模板的作用是补充「他不知道自己会说的信息」（发质、发量、打理），不是替代「他已经知道的信息」（想要什么）。

---

## 发质 × 剪法可行性对照（收表后必须应用）

**这张表只做排除，不做挑选。** 它回答的是「哪些剪法在你的发质下物理上做不到」，不回答「你应该剪哪个」。排除之后，剩下可行方案仍需用户在追问中自己选。

| 发质 | 物理可行 | 物理不可行 |
|---|---|---|
| 细软 / 发量少 | 高层次、打薄增加发根支撑、两侧推剪 | 低层次厚重、厚重齐刘海（贴头皮） |
| 粗硬 / 发量多 | 低层次或中层次 + **必须打薄** | 不打薄会炸开；层次过碎更炸 |
| 自然卷（沙发） | 顺卷保留长度 / 逆卷剪短防毛躁 | 按直发逻辑剪 |
| 发量少 + 想留长 | 必须高层次，否则贴头皮 | 厚重低层次 |

**用法**：用户在追问里选了某个方案后，若命中「物理不可行」列，必须提示并给同一维度下的替代，让用户重新选——**不要直接改成替代方案**。

---

## 打理频率 × 已选剪法的可维护性

**这张表不选发型，只做拦截。** 判据是「用户自己选的剪法，在TA的打理习惯下能不能维持」。

| 用户已选的剪法 | 打理投入要求 | 只肯简单吹两下时 |
|---|---|---|
| 低层次长发 | 每天吹 + 圆梳造型 | 三天内塌，不建议维持 |
| 高层次长发 | 每天吹出蓬松 | 效果打折明显 |
| 中层次+ 中等长度 | 简单吹两下可维持 | 可行 |
| 零层次短发 | 几乎免打理 | 可行 |

**硬约束**：拦截只针对用户**已经选定**的剪法。绝不能反向从打理频率推出「你该剪寸头」——那是造型推荐，超出本 Skill 范围。

---

## 长度底线设计（纠纷预防核心）

第 5 项「最不能接受的事」是**硬底线规则的输入源**，必须逐条转成指令卡的底线声明。

| 用户选择 | 指令卡底线写法 |
|---|---|
| 太短 | 「两侧不可再推剪」「发尾最多剪 Xcm」 |
| 两边被推光 | 「两侧保留至少 1cm，不推光」 |
| 显老 | 「不做全后梳，保留额前刘海」 |
| 显脸大 | 「两侧做收窄，不留鬓角碎发外扩」 |
| 头发炸开 | 「必须打薄去量，否则会炸开」 |

**追问底线时必须数字化。** 用户说「不能太短」→ 追问「最短能接受到哪里：耳上／耳垂／后颈？」

## 后续演进

- **P1**：加入「无法回答也没关系」的兜底文案，降低填表压力；长发修剪场景默认推送模板
- **P2**：接入照片辅助判断发质与脸型，替代部分字段；用户上传图后自动预填，减少手填
