# 理发指令卡模板

翻译结果的终点不是一段话，是一张**能直接递给师傅的卡片**。

## 使用规则

1. 卡片内容用第二人称「您」称呼用户本人，交给理发师看
2. 每一项都必须带具体数值或锚点，无「一点」「稍微」等模糊词
3. 底部硬底线区块不可省略
4. **溯源优先于填满**：用户没提到的维度，该行不输出，**不用默认值填空**。空着是合法的，替用户做主不是
5. 确实想加某一行的（如刘海），先在对话里问一句，用户点头后才写进卡片

---

## 两种输出形态

指令卡有两种用途，对应两种排版密度：

**形态一 · 对话内输出**（用户在聊天里看到的）——用紧凑列表，不用框线装饰。

```
【发型指令卡】

顶部留4cm，高层次从发中段起渐变
两侧高渐变 Fade，过渡带在耳上缘（从下往上推剪）
空气刘海，眉上 1cm，薄到能透光
发尾内扣 + 整体打薄去量

⚠️ 底线：两侧不可再推剪｜发尾最多剪 2cm｜刘海不能盖住眉毛
💡 剪到一半让我确认一次长度
```

**形态二 · 交给理发师**（用户复制或打印）——用完整框线版，含全部物理锚点。

以下完整示例即此形态。

## 完整示例（交给理发师）

```
═══════════════════════════════════════
【 发型指令卡 】
═══════════════════════════════════════

【长度】顶部保留约 4cm；发尾整体剪到锁骨上方约 5cm
       （对齐参照：耳朵上缘能盖住）

【层次】高层次，从发中段开始自然过渡，发尾打薄

【两侧】高渐变 Fade —— 从下往上推剪，
       过渡带在耳朵上缘，顶部与两侧有明显长度差

【后颈】圆颈线 —— 沿后颈发际线走连续弧线，中间不留平直台阶，
       收边在后颈发际线上方约 1cm

【刘海】空气刘海，眉上约 1cm，薄到能透光

【发尾】内扣，往里收，末端略呈 C 形

【打薄】发尾整体打薄去量，减少厚重感（发量偏多则加强打薄）

【整体约束】只修边与去量，不改变原有层次结构；总剪除量不超过 2cm

───────────────────────────────────────
⚠️ 硬底线（请务必遵守）
───────────────────────────────────────
· 两侧不可再往上推剪，我接受不了更短
· 发尾最多剪 2cm，超出这个长度我会要求重新调整
· 刘海可以短，但不能短到盖不住眉毛

───────────────────────────────────────
💡 请在剪到一半时让我确认一次长度
───────────────────────────────────────
· 尤其刘海和后颈层次，我看不到您视角

═══════════════════════════════════════
```

> 示例中的【后颈】【整体约束】两行，**只在用户说过对应需求时才出现**。这里是示范「有需求时该长什么样」，不是默认模板——照抄未提及的区块，就是溯源闸门说的越界。

```
⚠️ 底线：两侧不可再推剪，发尾最多剪 2cm
```

## 分区块填充规则

| 区块 | 内容要求 | 缺失时处理 |
|---|---|---|
| 长度 | 数字 + 参照锚点，区分顶部/侧面/发尾 | **必须追问，不得默认** |
| 层次 | 高/中/低/零 + 起始位置 | **不输出该行**。用户想要层次时追问层次类型，不要替他选「高层次」 |
| 两侧 | 渐变类型 + 过渡带位置 | 有明确需求才输出，否则标注「不两侧推剪」 |
| 后颈 | 形状（圆颈线／方颈线）+ 收边高度 | **不输出该行**。用户提「圆满」「台阶」时必须量化收边高度（后颈发际线上方 0-2cm） |
| 刘海 | 类型 + 位置 | **不输出该行**。没提刘海就不要塞空气刘海；用户想要时追问类型 |
| 发尾 | 内扣/外翻/齐 + 打薄与否 | **不输出该行**。内扣是审美选择，不能默认 |
| 打薄 | 打薄/削薄要求 + 去量程度 | 无需求则省略该行 |
| 整体约束 | 改动幅度上限（总剪除量／是否动结构） | 用户说过「修一下就行／别太短／保持原样」才有。**它不是维度，不许塞进长度行** |
| 照片坐标 | 指向照片中解剖位置的括号说明 | 无照片则不出现；有照片且用户确认过位置才写 |
| 硬底线 | **至少一条**，涉及剪除的维度都要覆盖 | **不可省略** |
| 过程确认 | 视觉盲区提醒 | 长发/刘海/后脑场景必含 |

**为什么删掉了默认值**：默认值是一种静默的审美决定。用户没提刘海，卡片里出现「空气刘海」——这不是翻译，是模型替用户选了样式，而且用户很可能不会注意到自己没要求过这一项。留空让用户看见「这一项你没提」，成本远低于剪完才发现。

---

## 照片坐标（仅当用户提供了照片）

照片是**核验证据**，不是新的维度。当某一行需要更精确的落点时，在该行后补一个括号坐标，指向照片里看得见的位置。

```
【长度】发尾剪到下颌线（正面照：下巴尖下方约两指）
【后颈】圆颈线（后面照：收边在颈线最高点上方约一指，中间不留平直台阶）
【两侧】鬓角保留到耳垂一半（侧面照）
```

规则：

1. 只用照片里**看得见的解剖位置**（耳垂、下颌、锁骨、颈线），不写 cm
2. 每条坐标必须对应一句**用户已经确认过**的话，不能凭空从照片加
3. 没照片就没有这个区块——它不是留白位，是不存在的区块

4. **要落到图上，先有两个可指认的锚点。** 模型不做图像识别，也不该猜像素位置。需要把坐标画到照片上时，先请用户在照片上指两个点（例：后颈边缘线的最低点、左右耳后竖线与颈侧的交界），再以这两点为基准写相对关系。**锚点由用户指认，模型只负责换算关系**——猜错一个锚点，整条线就偏出去了。

照片让坐标更精确，但**精确不等于授权**：照片里看到「后脑留了台阶」，不代表用户想要圆弧，得先问过。

## 反面示例（错误示范）

```
❌ 帮我剪短一点，两边弄短，加点层次感

问题：
- 「短一点」无量化
- 「弄短」无过渡带位置
- 「加点」暗示轻微但未定义
- 无底线声明
- 无过程确认
```

```
❌ 高层次+ Fade + 空气刘海+ 打薄一点

问题：
- 全是术语，无数值
- 理发师若不懂「高层次」起点定义则无法执行
- 无底线，无法防止过度剪除
```

```
❌ 用户只说「头发太塌了，想蓬松一点」，卡片写成：

【层次】高层次，从发中段起过渡
【两侧】高渐变Fade
【刘海】空气刘海
【发尾】内扣

问题（溯源失败）：
- 「刘海」「发尾」用户从未提及，是模型自己加的
- 「高层次」是模型替用户从蓬松需求里推出来的，用户没选
- 正确做法：追问「蓬松感你更想靠头顶撑起来，还是靠两侧剪短？」
  用户选了之后，才写对应的那一行
```

```
❌ 用户只说「稍微修一下就行」，卡片写成：

【长度】顶部剪短 3cm

问题（约束被误当维度）：
- 「修一下」描述的是改动幅度上限，不是某个部位的剪除量
- 翻译成「剪短 3cm」后，师傅会真的动结构，而用户本意是「别改」
- 正确写法：【整体约束】只修边，不改层次结构，总剪除量不超过 2cm
- 没把握时先追问：您说的「修一下」，是只修边不碰结构，还是可以动一点层次？
```

## 语气原则

- **面向理发师**：简洁、专业、可执行，不解释为什么
- **底线区块**：直接、坚定，不客气
- **过程确认**：以请求而非命令的语气提出

---

## 使用范围

本卡片仅覆盖**剪发**：剪裁五维（长度/层次/刘海/两侧/发尾）+ 打薄。

烫发与染发不在范围内。用户在指令卡中提出烫染需求时，明确说明本工具不处理该部分，不追加相关内容。

后续若扩展染发，需单独设计色号转换区块（涉及漂染决策与色度色调号体系）。
