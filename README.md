# 更适合中国宝宝体质的理发沟通转换器

把「剪短一点，但别太短」翻译成理发师能直接照着剪的指令。

一个 WorkBuddy Skill。本质是**歧义消除器**，不是术语查询器，更不是造型顾问。

---

## 它解决什么

理发纠纷的因果链几乎都一样：**顾客说得模糊 → 理发师按自己的刻度理解 → 长度不可逆 → 扯皮**。

真实判例里，顾客说「能扎上就行」，被理解成「反正下面也不要了」，一刀剪掉 60cm。问题不在理发师听不懂，而是**双方从来没对齐过同一把尺子**。

这个 Skill 做的事：在你进店之前，把嘴里的模糊形容逼问成位置、参照物和物理锚点。

---

## 三条设计原则

### 一、只翻译，不推荐

你说「想显脸小」，它不会告诉你适合什么发型，而是问你「想改的是两侧收窄、露额，还是发尾贴脸」。

**修饰意图是歧义题，不是设计题。** 效果描述不等于指定了改哪里，替你选就是拿走你的决定权。

判据是**溯源闸门**：指令卡上每一项都必须能回指到你说过的话。回指不到的，要么删掉，要么标 `[待确认]`。留空是合法的，未确认的默认值不是。

### 二、数字要落在你的参照系里

`3mm`、`5mm` 是理发师的**卡尺编号**，指推完留在头上的长度，不是你剪掉的量。说「留 5mm」，十个人里八个会听成「剪掉 5mm」——你以为自己选了个很保守的方案，实际是贴头皮推一遍。

所以追问只用你能验证的东西：

| 不这么问 | 这么问 |
|---|---|
| 剪 5cm | 剪掉三指并拢那么宽 |
| 推 3mm | 几乎能看到头皮 |
| 要圆寸吗 | 军训头那种？跟三天没刮的胡子差不多？ |

**先定结果，再定位置。** 长度要想象，结果（能不能扎起来、耳朵露不露）此刻就能回答。

### 三、照片是验证器，不是推荐器

你发照片，它只做一件事：**确认你说的和你实际的样子是不是一回事**。

- 可以：读现状（发尾到锁骨、后颈是圆弧还是留了台阶）
- 不可以：判断脸型、评价发质、推荐发型

照片看到的问题，还要回到你嘴里确认一次。**精确不等于授权**——照片里看到后脑留了台阶，不代表你想要圆弧。

## 怎么用

装到 WorkBuddy 的 skills 目录：

```bash
git clone https://github.com/kysan173-arch/haircut-communicator.git \
  ~/.workbuddy/skills/hair-terminology-translator
```

然后在对话里描述剪发需求即可，Skill 会自动触发。

> 仓库 slug 是英文（GitHub 不支持中文仓库名），中文名保留在仓库描述和本标题里。

## 测试

```bash
python scripts/check_static.py            # 148 项，退出码 0 = 通过
python scripts/check_lexicon_coverage.py  # 39 条
python scripts/run_behavior_test.py       # 打印 27 条用例，逐条实跑勾选
```

| 层 | 测什么 | 能自动吗 |
|---|---|---|
| L1 静态 | 规则在不在、反例有没有回流、换算有没有改错 | ✅ |
| L2 词典 | 真实原话能否反查到正确术语（含负样本防误命中） | ✅ |
| L3 行为 | 模型是否真的遵守规则 | ❌ 必须实跑 |

**L1 全绿不代表能用。** 它只证明规则写在文档里，不证明模型照着做。这个项目里反复出现过「文档写了、模型没照做」——所以每次改完都要实跑 L3。

## 已知边界

- **只做剪发。** 烫染明确不在范围内，提了会告知不覆盖，不给建议，不做术语翻译。
- **不做造型推荐。** 问「我适合什么发型」会被转成「你想让哪个部位有变化」。
- **不会在照片上画线。** 它能给出可执行的文字坐标（「沿现在这条边缘线、耳后竖线起弯」），但把线渲染出来需要宿主端支持。
- **不猜像素位置。** 需要标注时，锚点由你指认，它只负责换算相对关系。
